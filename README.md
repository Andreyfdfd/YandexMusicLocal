# YandexMusicLocal

Локальный музыкальный плеер для Windows: воспроизведение файлов с компьютера, поиск по библиотеке и интерфейс в духе современных музыкальных приложений. Проект не связан с Яндексом и не использует его закрытые ресурсы.

> **Статус:** активная переработка. Сейчас настраиваем структуру Git, переносим исходный код и затем будем последовательно оптимизировать запуск, сканирование медиатеки, кэш обложек и интерфейс.

## Цели разработки

- Быстрый запуск без полного повторного чтения всей музыкальной коллекции.
- Инкрементальное сканирование по пути, размеру и времени изменения файла.
- Чтение метаданных и обложек в фоновых задачах.
- Кэширование обложек на диске и в памяти с ограничением размера.
- Современный тёмный интерфейс с жёлтым акцентом, удобной библиотекой и нижней панелью проигрывателя.
- Переносимость: код и инструкции хранятся в GitHub, музыка и настройки остаются на каждом ПК локально.

## Среда разработки

- Windows 10/11
- PowerShell 7
- Python (рекомендуется использовать ту версию, которая указана в проверенной конфигурации проекта)
- VLC Media Player — нужен для варианта плеера на `python-vlc`

## Установка

Из PowerShell в каталоге проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

После добавления актуального файла приложения запуск будет выглядеть так:

```powershell
.\.venv\Scripts\python.exe .\interface_argon_optimized.py
```

Если Python 3.14 отсутствует, проверь установленную версию командой `py -0p` и создай окружение с доступной поддерживаемой версией.

## Структура

```text
YandexMusicLocal/
├── interface_argon_optimized.py  # актуальная точка входа (переносится из исходников)
├── requirements.txt              # Python-зависимости
├── scripts/
│   └── check-project.ps1         # базовая проверка исходников
├── docs/
│   ├── ARCHITECTURE.md
│   └── ROADMAP.md
├── .gitignore
├── .gitattributes
└── README.md
```

Структура будет уточняться после переноса и проверки существующего кода. Старые варианты интерфейса не назначаются точкой входа автоматически, чтобы случайно не запускать устаревшую версию.

## Данные пользователя

Музыкальная коллекция, SQLite-база конкретного компьютера, локальные настройки, кэш обложек, логи и готовые сборки не должны попадать в Git. Приложение должно создавать такие файлы в пользовательских каталогах Windows, а не рядом с исходниками.

## Работа с ветками

- `main` — стабильная версия.
- `develop` — интеграционная ветка разработки.
- `feature/*` — новые возможности.
- `fix/*` — исправления ошибок и производительности.

Перед объединением изменений необходимо проверить синтаксис Python и протестировать запуск на Windows.
